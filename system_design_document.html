1. Executive Summary & Problem Definition

In academic institutions like ABESEC Ghaziabad, physical pinboards and unstructured messaging groups lead to information clutter, missed deadlines, and delayed awareness of urgent circulars (e.g. examination datesheets, capstone guidelines, and placement drives).

The Department-Wise Digital Notice Board solves this by centralizing official campus announcements into a single, categorized, responsive web portal. It provides role-based authentication, instant filtering by department (CSE, ECE, Mechanical, Civil, Exam Cell, Placement Cell), live keyword searching, and full administrative notice management.

2. High-Level System Architecture

The system follows a modern Single-Page Application (SPA) architecture powered by React, bundled via Vite, and deployed on Render's global static distribution network.

4. Component Decomposition & Functional Modules

Component / Module Responsibility State & Event Handlers
Header Component Renders college banner (ABESEC Ghaziabad), portal title, and subtitle. Stateless presentation component.
User Auth Bar & Modal Displays current active role (Admin/Student/Guest) and triggers login popup. currentUser, showLoginModal, handleLogin(), handleLogout()
Department Bar Renders tab buttons for CSE, ECE, Mechanical, Civil, Exam Cell, Placement Cell, and All. selectedDept, setSelectedDept(dept)
Search Action Bar Captures keyword inputs and conditionally exposes notice publication button. searchTerm, setSearchTerm(text), showAddForm toggle
Notice Feed & Cards Renders filtered list of circulars with date stamps, department badges, and delete triggers. filteredNotices, handleDeleteNotice(id)
Notice Creation Form Captures title, department, and description inputs for publishing circulars. newTitle, newDept, newDesc, handleAddNotice()
Footer Component Displays developers credit, team attribution, and ABESEC copyright. Stateless presentation component.

5. Data Model Specification

The client-side state schema defines circular and authentication structures as follows:

Field Name Data Type Constraints Description
id Number / Timestamp Unique Primary Key Epoch timestamp generated on submission (e.g. Date.now()).
title String Required, Non-empty Headline of circular (e.g. "Capstone Project Synopsis").
department String / Enum Required CSE | ECE | Mechanical | Civil | Exam Cell | Placement Cell
date String (YYYY-MM-DD) Required Publication date generated automatically from system clock.
description String Required, Multiline Complete body text, instructions, deadlines, and contact info.

6. Non-Functional Requirements & Performance Metrics

  • Performance: Instant client-side filtering and search latency under 10 milliseconds for seamless user experience without server roundtrips.
  • Bundle Efficiency: Minified production assets (153 kB JS, 7.5 kB CSS, gzipped: ~51 kB) achieving a Lighthouse Performance score > 95.
  • Responsiveness: Fluid CSS Grid and Flexbox layouts guaranteeing full usability across smartphones, tablets, laptops, and digital hallway TV displays.
  • Reliability: 99.9% uptime powered by Render's automated static content delivery network.

7. CI/CD Deployment Workflow

  1. Code Commit: Developers commit and push updates to the main branch of the GitHub repository.
  2. Automated Trigger: Render detects the commit webhook and triggers the build pipeline.
  3. Build Execution: Render executes npm run build using Vite, compiling React JSX and CSS into production artifacts in /dist.
  4. Zero-Downtime Rollout: Live site updates automatically with instant cache invalidation.
